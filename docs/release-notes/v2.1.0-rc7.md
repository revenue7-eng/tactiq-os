**Release candidate — not for production.** Published for qualification and review.

## Threat coverage

## SLSA provenance scope

The attested source archive for this tag covers 4 of 27 top-level entries (`conf`, `recipes-core`, `recipes-kernel`, `scripts`), unchanged from rc5 and rc6. The BSP layer, build classes, `pki` and `security` sit outside the attested object, so a tampered recipe in the BSP layer is not detectable through provenance at this tag. The widening is committed on `main` after this tag was cut and applies from the next tag. The workflow comment inside this tag claims SLSA L3 intent, which the four-directory scope does not support.

## CVE posture

274 image-scoped, CVSS v3 base >= 7.0, status Unpatched (221 kernel, 53 userspace). rc6 was 134. This is honest disclosure, not a patched count. The kernel pin did not move and the CNA snapshot changed, so rc6 and rc7 numbers are not strictly like-for-like. The reproduction method is in the coverage manifest.

## Reproducibility

`rootfs.tar.gz` is bit-identical across two independent cold builds on different-generation cloud machines. That demonstrates determinism under fixed inputs, not fixation of the inputs: the seven Yocto layers are not pinned by any manifest.

## Signing

The PKI is development-only, with deliberately published private keys (`pki/README.md`). A build gate (`TACTIQ_KEYRING`) makes it mechanically impossible for the development root to enter a production image.

No OTA bundle ships with this release. Bundle build and signature verification were exercised end to end from the unified PKI tree and are recorded in the coverage manifest, but a bundle signed with deliberately published development keys carries no integrity guarantee for a downloader. Reproduce one from the tag if you need it.

No measured boot, no TPM on this board, no fused OTP, no hardware root of trust.
