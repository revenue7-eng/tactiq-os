# TactiQ OS v2.1.0-rc6

**Release candidate — not a GA release.** This image is published for
qualification and review. The CVE posture below is honest disclosure of
scanner output, not a patched count; driving it to zero is a GA gate, not an
rc6 gate.

Built from a complete Yocto *wrynose* build (`20260718113035`); verified
booting on Radxa Rock 5A (RK3588S) with SELinux in enforcing mode.

## Changes since rc5

rc5 was the toolchain migration. rc6 is a correctness release: four defects
were found in metadata and update packaging, all of which had been shipping
silently since before rc5.

- **`DISTRO_VERSION` 2.0.0 → 2.1.0.** The release series has been `v2.1.0-*`
  since rc1, but `DISTRO_VERSION` was never bumped. It lands in
  `/etc/tactiq-release` via `tactiq-release.bb` and is part of the
  attestation payload, so every image through rc5 reported a version the
  project had not used since v2.0.1.
- **The OTA bundle now carries the production rootfs.** `RAUC_SLOT_rootfs`
  pointed at `tactiq-image-dev` — a bring-up default that was never
  revisited. Any released bundle would have carried the development rootfs,
  with `debug-tweaks` and an SSH server, into a production A/B update.
- **Bundle version derives from `DISTRO_VERSION`.** It was pinned to a
  literal `1.0.0`, unrelated to the OS version it carried.
- **`/etc/tactiq-release` records the release commit.** `TACTIQ_META_GIT_REV`
  was read from the process environment, which bitbake filters, so the field
  read `unknown` in every prior release.

### Verified on hardware

- **SELinux enforcing on the production image.** Enforcing at audit timestamp
  1.364 s, policy load at 1.520 s (156 ms later; 158 ms by the printk clock).
  Zero AVC denials on the boot path to the login prompt.
  Evidence: `measurements/selinux-enforcing-boot-prod-20260717.log`.
  Scope limit, stated deliberately: what is proven is zero AVC among all
  visible audit records plus the first suppression window at 5.403 s
  (21 callbacks, fully accounted for by sequence numbering). A second window
  at 20.679 s (76 callbacks) surrounds a failed root login and is not
  accounted for; AVC in the 7–20 s range cannot be excluded from that log.
  Boot reached multi-user well before it, so the boot-path claim stands.
  The failed root login is itself evidence of the intended posture: the
  production image has no shell.
- **RAUC A/B rollback.** Corrupting the target root slot to an unmountable
  state causes fallback to the healthy slot after three failed boot attempts.
  Slot selection needs no operator action — the boot-count logic runs in
  U-Boot. Evidence: `measurements/rauc-rollback-test-20260716.md`.
- **Boot partition labeled at build time** (WIC rawcopy of
  `tactiq-boot-image`), so boot content carries SELinux labels rather than
  being relabeled on first boot.

## CVE posture

**134 image-scoped, CVSS v3 base ≥ 7.0, status `Unpatched`**
(108 kernel, 26 userspace). rc5 reported 35 (21 kernel, 14 userspace).

This is a real regression, not a change of definition or scope. The kernel
pin did not move between rc5 and rc6 — both are `6.18.24+git` — and 85 of the
108 kernel entries are `CVE-2026-*` published in the month since rc5 was cut.
Userspace grew the same way, mostly `openssl` (9) and `glibc` (5).

Moving the pin is tracked in
[#55](https://github.com/revenue7-eng/tactiq-os/issues/55) and was
deliberately excluded from rc6 so that the enforcing-boot and OTA
verification in this release are measured against an unchanged software base.

### Reproducing the figure

The number is scoped to what is actually installed. Package names and recipe
names differ (`libc6` → `glibc`, `libselinux1` → `libselinux`), so comparing
the two lists by string equality silently drops most of the image and gives a
wrong answer.

```sh
# 273 installed packages -> 70 recipes
awk '{print $1}' manifest-rock5a.txt | sort -u > pkgs.txt
oe-pkgdata-util lookup-recipe $(cat pkgs.txt) | sort -u > recipes.txt

# count Unpatched, CVSSv3 >= 7.0, restricted to those recipes
python3 - <<'EOF'
import json
rec = set(open('recipes.txt').read().split())
d = json.load(open('cve-rock5a.enriched.json'))
hits = [(p['name'], i['id']) for p in d['package'] for i in (p.get('issue') or [])
        if i.get('status') == 'Unpatched' and i.get('scorev3')
        and float(i['scorev3']) >= 7.0 and p['name'] in rec]
print(len(hits))
EOF
```

Without the scope filter the same report yields 141; the difference is
`libxml2`, `python3` and `sqlite3`, which are not installed. The kernel
qualifies via the `kernel-base` RPROVIDES. Breakdown by detail:
`version-in-range` 110, `no-version-ranges` 24.

Do **not** quote `cve-rock5a.sbom-cve-check.yocto.json` as the posture — it is
the raw input over a wider scope and gives a different, larger number.

## OTA update path

The bundle is signed with `TactiQ RAUC Dev Signing`; the image ships its
issuer, `TactiQ RAUC Dev CA`
(SHA1 `58:66:EE:7C:F2:4B:32:3C:CB:37:BB:BA:F1:EA:50:EE:CF:94:C2:C7`), as
`/etc/rauc/ca.cert.pem`. The chain closes, so `bundle-rock5a.raucb` will
install on this image.

That is an availability property, not an authenticity one. **The CA private
key is in this repository**, so anyone can produce a bundle this image
accepts. Integrity of the bundle as a release asset rests on the cosign
signature over `SHA256SUMS`, exactly like every other asset — not on its CMS
signature. Update authentication arrives with a production PKI
(hardware-anchored, offline root), which is not in this release.

## Known limitations

- **No measured boot.** PCR 0–9 are not measured, the bootloader is not
  measured-boot-aware, RK3588 OTP fuses are not burned, FIT image signing is
  not enabled.
- **Filesystem-image reproducibility is unmeasured** under wrynose. The rc4-era
  figure does not carry over. Do not claim reproducible builds for rc6.
- **No provenance binding for the binaries.** SLSA provenance covers the
  source archive only; the image is built locally, not in a hosted builder.
  A compromise of the build host would produce artifacts that pass every
  consumer-side check. See `IA-0001` in the coverage manifest, which is
  `partial` for this reason.
- **The attestation agent is a stub.** `/opt/tactiq/bin/tactiq-agent` is a
  placeholder script; see `ATTESTATION.md`.
- **Build identity delta.** The image was built at commit `d99725b`; the tag
  is at `9c51838`. The difference is one file,
  `security/coverage-rock5a.v2.1.0-rc6.yaml`, which does not affect the
  rootfs. `/etc/tactiq-release` therefore records the parent commit.
- **`TACTIQ_META_GIT_REV` is supplied through `local.conf`,** which is not in
  the repository, so the value is not reproducible from a clean clone.
  `TACTIQ_IMAGE_NAME` is empty and `TACTIQ_BUILD_DATE` is the fixed
  `SOURCE_DATE_EPOCH` used for reproducibility. All three are metadata
  defects scheduled for rc7.
- **VEX not published.** Three SELinux-family entries match the rc5
  not-applicable finding — the vulnerable `seunshare` tool is not packaged —
  but this is not yet machine-readable.

## Verification

See `VERIFY.md`. `SHA256SUMS` carries a keyless cosign workflow-identity
signature (`SHA256SUMS.workflow.{pem,sig}`) produced by the `release-sign`
workflow on the tag. Unlike rc5, this release carries **only** the
workflow-identity signature; no maintainer personal-identity signature was
issued.

```sh
cosign verify-blob SHA256SUMS \
  --certificate SHA256SUMS.workflow.pem \
  --signature SHA256SUMS.workflow.sig \
  --certificate-identity "https://github.com/revenue7-eng/tactiq-os/.github/workflows/release-sign.yml@refs/tags/v2.1.0-rc6" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com"
```

Rekor transparency-log index for this signature: **`2194858421`**.
Web UI: <https://search.sigstore.dev/?logIndex=2194858421>.

The coverage manifest deliberately records no Rekor index of its own: it is
hashed into `SHA256SUMS` before the log entry exists, so a forward reference
could not be verified. The entry is found by searching for the sha256 of
`SHA256SUMS`.
