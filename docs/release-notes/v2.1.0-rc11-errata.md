# v2.1.0-rc11 errata

The v2.1.0-rc11 release assets and their signatures are unchanged. This
document records two defects found after publication. Neither affects the
published PCR reference, the boot measurements it describes, `SHA256SUMS` or
any signature.

Both were found in the rootfs of build `20260922161055`, the build published
as v2.1.0-rc11 (`/etc/tactiq-release` read from
`tactiq-image-tactiq-rock5a.rootfs-20260922161055.ext4`).

## 1. The image identifies itself as v2.1.0-rc9

`/etc/tactiq-release` in the rc11 image reads:

    TACTIQ_OS_VERSION=2.1.0
    TACTIQ_OS_CODENAME=hardened-edge
    TACTIQ_BUILD_DATE=2011-04-05T23:00:00Z
    TACTIQ_BUILD_MACHINE=tactiq-rock5a
    TACTIQ_META_TACTIQ_GIT=v2.1.0-rc9
    TACTIQ_IMAGE_NAME=

`TACTIQ_META_TACTIQ_GIT` comes from
`recipes-core/tactiq-release/release-rev.inc`, which is set by hand before a
release is tagged. At the tag `v2.1.0-rc11` the file still reads
`v2.1.0-rc9`. The step was missed and nothing checked it.

Impact: a device running rc11 reports the revision of rc9. The file is not
measured into PCR 0 to 9, so boot measurements and the published reference
are correct. Do not use `TACTIQ_META_TACTIQ_GIT` to tell an rc11 image from
an earlier one; compare the release assets against the rc11 `SHA256SUMS`
instead.

## 2. A known issue was dropped from the rc11 coverage manifest

`TACTIQ_IMAGE_NAME` is empty and `TACTIQ_BUILD_DATE` is the fixed
`SOURCE_DATE_EPOCH` fallback (2011-04-05). This has been true since rc6 and
was listed as a known issue in the rc6 release notes and in the coverage
manifests of rc6, rc7 and rc10. The rc11 coverage manifest does not list it,
although the rc11 image still has it (see the file above).

The coverage manifest is pinned to the tag and covered by the release
signature, so it is not edited. This errata is the correction.

## Remedy

Both defects come from manual release steps with no check behind them. The
next release adds two checks to `scripts/mk-release.sh`, so that a release
cannot be assembled when either recurs:

- the identity in `/etc/tactiq-release`, read from the release image itself,
  must name the tag being released, the machine and the image;
- every known issue in the previous release's coverage manifest must either
  appear in the new one or be marked as resolved.

The empty image name and the fixed build date are addressed in the same
change.
